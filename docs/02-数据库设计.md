# 企业健康管理平台 — 数据库设计

## 概览：19 张表，分 5 个域

| 域 | 表数 | 包含 |
|------|------|------|
| 组织与权限 | 6 | department, user, role, user_role, menu, role_menu |
| 体检管理 | 6 | exam_package, exam_package_item, exam_schedule, schedule_dept, exam_record, exam_result_item |
| 风险评估 | 2 | health_risk_rule, health_risk_result |
| 干预随访 | 3 | intervention_plan, intervention_participant, follow_up_record |
| 系统日志 | 2 | operation_log, login_log |
| **合计** | **19** | |

注：比初版加了 `schedule_dept` 关联表。

## 3. 风险评估（2 表）

### health_risk_rule 风险评估规则表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | PK |
| package_item_id | bigint | FK → exam_package_item.id（关联到具体指标） |
| rule_name | varchar(64) | 规则名称 |
| risk_level | tinyint | 触发风险等级：1=低 2=中 3=高 |
| condition_type | varchar(16) | `gt`(大于阈值) / `lt`(小于阈值) / `out_of_range`(超出参考范围) / `equals`(等于，用于定性指标) |
| threshold_value | varchar(32) | 自定义阈值（gt/lt/equals 时使用；out_of_range 时留空，使用 package_item 的 ref_min/ref_max） |
| score | int | 触发此规则时的风险分数 |
| weight | decimal(3,2) | 权重，默认 1.0 |
| status | tinyint | 0=禁用 1=启用 |

说明：`threshold_value` 与 `condition_type` 配合使用，解决了同一个指标不同风险等级需要不同阈值的问题。

示例 1 — 定量指标（BMI，ref_min=18.5, ref_max=24）：
```
规则A: condition_type='gt', threshold_value='28', risk_level=3, score=30, weight=1.0
       → BMI>28 → 高风险，+30分
规则B: condition_type='gt', threshold_value='24', risk_level=2, score=15, weight=0.8
       → BMI>24 → 中风险，+15×0.8=12分
规则C: condition_type='out_of_range', threshold_value=null, risk_level=1, score=5, weight=0.5
       → BMI<18.5 或 >24 → 低风险，+5×0.5=2.5分
```
注意规则A和B的阈值不同但指标相同，靠 `threshold_value` 区分，而非靠 `package_item.ref_max`。

示例 2 — 定性指标（尿蛋白，ref_min=null, ref_max=null）：
```
规则: condition_type='equals', threshold_value='阳性', risk_level=2, score=20, weight=1.0
      → 检测值="阳性" → 触发，+20分
```

### health_risk_result 风险评估结果表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | PK |
| user_id | bigint | FK → user.id |
| record_id | bigint | FK → exam_record.id |
| total_score | decimal(5,1) | 综合风险评分（所有触发规则的加权总分） |
| risk_level | varchar(8) | 综合等级：低（<20）/ 中（20-50）/ 高（>50） |
| detail_json | text | 各规则命中明细 JSON |
| assessed_at | datetime | 评估时间 |

## 4. 干预随访（3 表）

### intervention_plan 干预计划表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | PK |
| title | varchar(128) | 计划名称 |
| type | varchar(32) | 干预类型（lecture/exercise/weight/smoking/mental） |
| description | text | 计划说明 |
| start_date | date | 开始日期 |
| end_date | date | 结束日期 |
| executor_id | bigint | 执行人 user.id |
| status | tinyint | 0=未开始 1=进行中 2=已结束 |
| created_by | bigint | 创建人 |
| created_at | datetime | |

干预类型用 Java enum 维护，不建字典表：
```java
public enum InterventionType {
    LECTURE("健康讲座"),
    EXERCISE("运动计划"),
    WEIGHT("减重管理"),
    SMOKING("戒烟计划"),
    MENTAL("心理辅导");
}
```

### intervention_participant 干预参与表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | PK |

## 完整关系基数表

### 一对一 (1:1)

| 表A | 表B | 关联字段 | 约束 | 说明 |
|------|------|------|------|------|
| exam_record | health_risk_result | record_id | UNIQUE(record_id) | 一条体检记录只评估一次，重新评估覆盖旧结果 |

### 一对多 (1:N)

| 主表 (1) | 从表 (N) | 外键 | 说明 |
|------|------|------|------|
| department | department | parent_id | 部门树自引用，顶级为 0 |
| department | user | dept_id | 一个部门 N 个员工 |
| user | exam_record | user_id | 一个员工 N 次年检记录 |
| user | operation_log | user_id | 一个用户产生 N 条操作日志 |
| user | intervention_participant | user_id | 一个员工参与 N 个干预计划 |
| user | follow_up_record | user_id | 一个员工有 N 条随访记录 |
| exam_package | exam_package_item | package_id | 一个套餐包含 N 个指标 |
| exam_package | exam_schedule | package_id | 一个套餐被 N 次排期复用 |
| exam_schedule | exam_record | schedule_id | 一次排期产生 N 条体检记录 |
| exam_record | exam_result_item | record_id | 一条记录有 N 个检测指标值 |
| exam_package_item | exam_result_item | package_item_id | 一个模板指标被 N 条结果引用 |
| exam_package_item | health_risk_rule | package_item_id | 一个指标可配 N 条风险规则（不同阈值不同等级） |
| intervention_plan | intervention_participant | plan_id | 一个计划分配 N 个参与者 |
| intervention_plan | follow_up_record | plan_id | 一个计划有 N 条随访记录 |

### 多对多 (M:N)

| 表A | 表B | 中间表 | 说明 |
|------|------|------|------|
| user | role | user_role | 一个用户可有多个角色（如同时是 leader + employee） |
| role | menu | role_menu | 一个角色关联 N 个菜单，一个菜单分配给 N 个角色 |
| user | intervention_plan | intervention_participant | 一个员工参与 N 个计划，一个计划包含 N 个员工 |

### 特殊说明

| 关系 | 说明 |
|------|------|
| login_log | 无外键，独立日志表。username 冗余存储，用户被删后日志仍可追溯 |
| health_risk_rule | 与 exam_package_item 是 1:N，但不同规则通过 `condition_type` + `threshold_value` 组合区分（如 BMI>28 高风险 vs BMI>24 中风险） |
| user_role M:N | 种子数据每人一个角色，但表结构支持多角色。`DataScopeUtil` 取所有角色中 `data_scope` 最小值（最宽松的权限），确保 leader 角色不会被 employee 角色的 scope=2 限制 |
| exam_record → health_risk_result | `assess()` 方法先 DELETE 旧结果再 INSERT 新结果，配合 UNIQUE(record_id) 保证 1:1 |
