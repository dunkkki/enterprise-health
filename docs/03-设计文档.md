# 企业健康管理平台 — 设计文档

## 1. 技术选型

| 层 | 技术 | 版本 | 选型理由 |
|------|------|------|------|
| 后端框架 | Spring Boot | 3.3.5 | 2024 年稳定版，生态成熟 |
| ORM | MyBatis-Plus | 3.5.7 | boot3-starter，零 SQL 做 CRUD |
| 数据库 | MySQL | 8.0 | 结构化数据 + 窗口函数 |
| 缓存 | Redis | 7.x | Session + 热点数据 + 排行榜 |
| 权限框架 | Sa-Token | 1.38+ | 比手写拦截器专业，支持 RBAC 注解鉴权 |
| Java | JDK | 17 | Spring Boot 3 最低要求 |
| 构建 | Maven | 3.x | |
| 前端 | Vue 3 + Vite | 5.x | Composition API |
| UI 框架 | Element Plus | 2.9+ | 企业后台标配，桌面端原生风格 |
| 图表 | ECharts | 5.x | |
| Excel | EasyExcel | 3.x | 阿里出品，流式读写大文件 |

### 为什么换 Sa-Token 替代手写拦截器
- 银河健康手写了 Session+Redis 拦截器 → 功能能用但不专业
- Sa-Token 提供：`@SaCheckRole("hr")` 注解鉴权、菜单权限 `@SaCheckPermission`、登录态、踢人下线、二级认证
- 毕设答辩时这是加分项："选了业界成熟的 RBAC 方案而非手写"

### 数据权限设计（解决"部门主管只看本部门"的问题）

`role` 表增加 `data_scope` 字段：

| data_scope | 含义 | 对应角色 |
|------|------|------|
| 0 | 全部数据 | admin, hr |
| 1 | 本部门数据 | leader |
| 2 | 仅本人数据 | employee |

在 Service 基类或工具类中，查询前检查当前用户角色的 data_scope，动态拼接过滤条件：
- scope=0：不加过滤
- scope=1：WHERE dept_id = 当前用户部门
- scope=2：WHERE user_id = 当前用户 ID

这样"部门主管"登录后看到的是缩小版 Dashboard（只统计本部门），用户列表也只显示本部门员工。

## 2. 系统架构

```
浏览器 (Vue 3 + Element Plus)
    │
    ├── /api/* ──→ Spring Boot (8080)
    │                  │
    │                  ├── Sa-Token 拦截器（登录 + 角色 + 权限）
    │                  │
    │                  ├── Controller 层（14 个）
    │                  ├── Service 层（业务逻辑）
    │                  ├── Mapper 层（MyBatis-Plus）
    │                  │
    │                  ├── MySQL 8.0（enterprise_health 库，18 表）
    │                  └── Redis（Session + 缓存）
    │
    └── 静态资源 (Vite 打包，Nginx 反向代理，也可 Vite dev server)
```

```
com.enterprise.health
```

## 4. 前端设计

### 布局方案：经典后台管理布局

```
┌──────────────────────────────────────────┐
│  Logo       顶部导航栏     用户头像 退出  │
├────────┬─────────────────────────────────┤
│        │                                 │
│ 侧边栏  │        内容区域                 │
│ 菜单    │   （面包屑 + 页面内容）          │
│        │                                 │
│ 可折叠  │                                 │
│        │                                 │
└────────┴─────────────────────────────────┘
```

- 左侧 220px 可折叠菜单，Element Plus `el-menu` 的 collapse 模式
- 顶部 56px，含 Logo、用户头像、通知铃铛
- 内容区全宽自适应，**不做 max-width 限制**
- 面包屑在内容区顶部

### 角色 → 菜单对应

| 角色 | 可见菜单 |
|------|---------|
| 超级管理员 | 全部菜单（含系统管理、日志） |
| HR 经理 | 员工管理、体检套餐、排期、报告、风险、干预、看板 |
| 部门主管 | 看板（仅本部门）、员工体检记录（仅本部门）、风险评估 |
| 普通员工 | 我的体检报告、我的风险、我的干预计划 |

### 前端路由设计

```
/login                     # 登录页
/                          # 主布局（侧边栏+顶栏，根据角色渲染不同菜单）
  /dashboard               # 首页数据看板（admin/hr/leader 可见）
  /org                     # 组织架构（admin/hr 可见）
    /org/dept              # 部门管理
    /org/user              # 员工管理
  /exam                    # 体检管理（admin/hr 可见）
    /exam/package          # 体检套餐
    /exam/schedule         # 体检排期
    /exam/record           # 体检记录录入与查看
  /risk                    # 风险评估（admin/hr/leader 可见）
    /risk/rules            # 评估规则配置
    /risk/results          # 评估结果列表
  /intervention            # 干预管理（admin/hr/leader 可见）
    /intervention/plan     # 干预计划
    /intervention/follow   # 随访记录
  /system                  # 系统管理（仅 admin 可见）
    /system/role           # 角色管理
    /system/menu           # 菜单管理
    /system/log            # 操作日志
  /my                      # 个人中心（所有角色可见）
    /my/exams              # 我的体检报告
    /my/risks              # 我的风险评估
    /my/interventions      # 我的干预计划
    /my/profile            # 个人信息+修改密码
```

员工登录后的侧边栏菜单：数据看板（仅看自己）、我的体检、我的风险、我的干预、个人信息。
部门主管额外可见：部门数据看板、部门员工体检记录、部门风险评估结果。
菜单的可见性由后端 `/api/auth/me` 返回的菜单树控制，前端根据返回值动态渲染。

### 视觉风格：专业企业后台

与星河健康的"深空治愈"路线彻底切割，走**标准企业后台**风格：

- 配色：白底（#fff）+ 浅灰背景（#f0f2f5）+ 蓝色主色（#409EFF，Element Plus 默认）
- 侧边栏：深蓝黑底（#001529）+ 白色文字，el-menu 标准暗色模式
- 内容区：白色卡片 + 细边框，信息密度高，一眼看到更多数据
- 字号：表格/表单 14px，标题 16-20px，不做花哨的大字号
- 不搞暗色模式切换、星空特效、渐变——企业后台追求的是**清晰、高效、专业**
- 参考：若依（Ruoyi）、Ant Design Pro 的后台风格

关键区别 vs 星河健康：
| | 星河健康 | 企业健康管理 |
|------|---------|-----------|
| 定位 | C 端健康 App | B 端后台管理 |
| 布局 | 640px 窄条 + 底部 TabBar | 全宽侧边栏 + 顶栏 |
| 配色 | 深空暗色 | 白底蓝主色 |
| 字号 | h1=24px, h2=20px | h1=20px, h2=16px（紧凑） |
| 信息密度 | 低（移动端大触控区） | 高（桌面端表格/表单） |
