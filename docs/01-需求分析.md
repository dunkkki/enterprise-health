# 企业健康管理平台 — 需求分析

## 1. 项目背景

企业每年为员工安排体检。HR 负责：制定套餐 → 安排排期 → 收集纸质报告 → 手动整理 Excel → 通知异常员工复查 → 跟踪干预效果。

整个过程**手工、低效、无数据沉淀**。本系统将体检管理、健康风险评估、干预计划跟踪整合为统一平台，让 HR 从 Excel 里解放出来。

**目标用户群体**：200-2000 人规模企业的 HR 部门、管理层、全体员工。

---

## 2. 用户角色

| 角色 | 编码 | 人数 | 数据范围 | 核心诉求 |
|------|------|------|------|------|
| 超级管理员 | admin | 1-2人 | 全部 | 系统配置、菜单权限分配、操作审计 |
| HR 经理 | hr | 3-5人 | 全部 | 管理员工档案、排期体检、查看报表、录入结果 |
| 部门主管 | leader | 各部门1人 | 本部门 | 查看本部门员工健康概况、异常指标分布 |
| 普通员工 | employee | 全员 | 仅本人 | 查看个人体检报告、健康风险、参与干预计划 |

**数据范围规则**：role 表 `data_scope` 字段控制。Service 层统一通过 `DataScopeUtil` 过滤查询，不每个接口手写权限判断。多角色用户取最小 scope（最宽松）。

**菜单权限**：`menu` 表三级结构（目录→菜单→按钮），`role_menu` 关联表分配权限。`@SaCheckPermission` 注解鉴权，后端从数据库动态加载。

### 模块四：体检记录

| 编号 | 功能 | 可见角色 | 优先级 | 说明 |
|------|------|------|------|------|
| R-01 | 记录列表 | admin/hr | P0 | 分页表格：员工、排期、状态、体检日期、结论。支持按排期、部门、状态筛选 |
| R-02 | 录入结果 | admin/hr | P0 | 逐项填写检测值；系统根据套餐项目的参考范围自动判断 is_abnormal（正常/偏高/偏低）；记录录入人 |
| R-03 | 记录详情 | admin/hr | P0 | 查看员工某次体检的全部指标值及异常标记，模板回填显示指标名称、单位、参考范围 |
| R-04 | 我的体检 | 所有人 | P0 | 员工查看自己历年体检记录 |
| R-05 | 打印报告 | admin/hr | P2 | HTML 打印页，@media print |

**业务规则**：
- 一个人在同一排期内只有一条 exam_record（UNIQUE 约束）
- 指标异常判断：检测值 < ref_min → 偏低(2)；检测值 > ref_max → 偏高(1)；在范围内 → 正常(0)
- 录入结果时同时写入 `updated_by`（录入人ID）

### 模块五：健康风险评估

| 编号 | 功能 | 可见角色 | 优先级 | 说明 |
|------|------|------|------|------|
| K-01 | 规则列表 | admin/hr | P0 | 表格：规则名称、关联指标ID、条件类型、阈值、分数、权重、触发等级 |
| K-02 | 新增规则 | admin/hr | P0 | 选择体检指标、设定条件类型（gt/lt/out_of_range/equals）、阈值、分数、权重、风险等级 |
| K-03 | 编辑/删除规则 | admin/hr | P0 | 修改规则参数；删除规则 |
| K-04 | 评估结果列表 | admin/hr/leader | P0 | 分页表格：员工、排期、总分、等级、评估时间。按部门、风险等级筛选 |
| K-05 | 执行评估 | admin/hr | P1 | 对一条已录入结果的体检记录执行评估；遍历该记录所有指标值，匹配全部启用规则，加权计算总分；总分>50=高，20-50=中，<20=低；评估结果覆盖旧数据 |
| K-06 | 我的风险 | 所有人 | P0 | 员工查看自己历次评估结果 |

**业务规则**：
- 规则引擎四步：遍历指标值 → 匹配启用规则 → 条件判断（gt/lt/out_of_range/equals）→ 加权计分
- 总分 = Σ(命中规则分数 × 权重)，权重默认 1.0
- 一条 exam_record 只有一条评估结果（UNIQUE 约束），重新评估覆盖旧值
- 评估明细（哪些规则被命中）存为 JSON 快照在 detail_json 字段

## 5. 业务规则汇总

| 规则 | 说明 |
|------|------|
| 密码加密 | BCrypt，登录时验证，存储不可逆 |
| 雪花ID | 全局使用 MyBatis-Plus ASSIGN_ID，Jackson Long→String 序列化防 JS 精度丢失 |
| 数据权限 | role.data_scope 驱动，Service 层统一过滤 |
| 权限鉴权 | @SaCheckPermission 注解 + 数据库动态加载 |
| 异常判断 | 检测值与套餐项目 ref_min/ref_max 比较 |
| 风险评估 | 加权计分 = Σ(规则分数 × 权重)，总分分段判定等级 |
| 排期联动 | 创建排期/启动排期时自动为目标部门员工生成记录 |
| 物理删除 | 无逻辑删除字段，外键 CASCADE/SET NULL/RESTRICT 维护引用完整性 |
| 操作日志 | AOP 自动记录，不侵入业务代码；登录失败时记录到 login_log |
| 排期状态 | 0=未开始 1=进行中 2=已截止；启动排期时重新为目标部门员工补录记录 |

## 6. 验收标准

| 模块 | 验收项 | 标准 |
|------|------|------|
| 登录 | 4种角色分别登录 | 各自的菜单树正确、数据范围正确 |
| 部门 | CRUD + 树展示 | 创建3级部门、删除有子部门的被拒绝 |
| 员工 | 搜索 + 筛选 + 导入 | 按姓名模糊搜、按部门筛选、Excel 导入10条 |
| 排期 | 创建 → 自动生成记录 | 创建带3个目标部门的排期，确认每个部门的员工都生成了 exam_record |
| 体检 | 录入结果 → 自动标异常 | 填血压150/95，确认 is_abnormal=1 |
| 风险 | 配置规则 → 执行评估 | 给"收缩压>140"配规则，对异常记录执行评估，确认命中并计分 |
| 干预 | 创建计划 → 分配人 → 随访 | 创建减重计划→拉2个员工→新增2条随访记录 |
| 权限 | 不同角色登录 | leader01 只能看到技术部数据，emp01 只能看到自己的体检和风险 |
| 日志 | 操作日志记录 | 新增/编辑/删除任意数据后在操作日志中看到记录 |
| 数据 | 完整性 | 无孤儿记录，外键约束不报错，级联删除正常工作 |
